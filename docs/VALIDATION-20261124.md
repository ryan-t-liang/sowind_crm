## 实现

- GP/UN 前端重做服务、预约表单、认证作品、我的、预约列表、详情双页签、工单时间线、快递单号弹层与签收确认。
- 使用设计中下载的本地素材；表单、选择、弹窗和折叠区复用 shadcn/Radix 组件。清除旧版全局业务样式对新页面的干扰。
- 三个同域包共用版本化 LocalStorage 工单模型。提交创建独立工单，修改回填原记录；取消归档保留；后台审核、物流、报价、图片与备注同步到用户端，客户寄回及签收操作同步到后台。
- 后台保留会员、线索代码；售后新增门店电话、拒绝原因、物流纠正、图片预览、有效金额校验、报价/付款确认、可选订件分支、签收确认及并发编辑提示。
- 旧版后台存储保留，并在首次使用新版数据模型时迁移。旧文件名不会被当作真实图片显示。

## 范围与差异

- 纯前端原型，跨端联动仅限同域名、同浏览器；没有真实后端、微信身份、支付、物流查询或上传服务，未做实体手机测试。
- 已交给门店实物处理的预约不能在用户端取消/修改；保留设计按钮位置并禁用。签收只在作品寄回后开放。
- 当前稿“我的”只展示最新一条预约，完整记录在“查看全部”；旧Excel的最近三条要求以本次严格照稿要求为准。
- GP未提供独立养护长页，了解养护入口展示GP FAQ中的完整保养项目。UN采用设计中的15步骤长页。
- FAQ稿中未展开的问题没有答案正文，交互展开时补充与现有服务流程一致的短答。服务条款没有提供品牌正式完整正文，保留原型说明。
- 保留原稿中的跨品牌素材与文字；旧版额外添加的流程条和未经核实的邮箱不再插入当前稿件。
- `FUNCTION-AUDIT-1120.md` 为历史记录，旧PASS存在证据不足，不能代替本次交互验证。

## 反馈修正

- 预付费维修流程最终状态文案为：`门店已收件，检测及报价中` → 可选的 `维修配件订购中` → `维修中` → `维修完成，待寄回`。无需订件时可在报价和付款确认后直接进入维修。
- “门店已收件，检测及报价中”必传作品收件图片；“维修完成，待寄回”必传维修完成图片及服务说明。两组图片使用独立字段，用户时间线与后台详情分别展示，不复用同一组图片。
- 作品认证确认卡补齐品牌对应腕表图片：GP 显示 Laureato 桂冠系列，UN 显示 Freak 奇想系列；型号与作品编号继续保留在同一卡片中。
- 新工单号统一为 `GPAS` 或 `UNAS` 加10位随机数字，并在生成时检查当前浏览器数据避免重复。LocalStorage 数据升级到v5；首次读取旧v4/v3数据时，旧 `payment` 工单迁移为“维修完成，待寄回”，并在寄回前要求重新核实付款；两类图片保持独立。
- 后台、GP H5、UN H5 均提供中英文切换；语言选择保存在同域 LocalStorage，跨三个原型同步并在刷新后保留。状态筛选、详情进度、时间线、主要表单、导航、提示与 FAQ/养护内容均随语言切换。
- 后台筛选区为“查询字段、查询内容、品牌、工单状态、操作”五段式布局，门店并入查询字段，删除日期筛选。列表操作按钮扩大并固定，四个新增业务阶段使用不同状态色；当前处理区统一控件间距、上传区与确认行样式。
- 模型测试覆盖100个随机工单号的格式与唯一性、v3/v4迁移、订件与直接维修两条分支、报价/付款前置校验，以及两个图片节点的独立必传和持久化。浏览器回归同时检查GP/UN品牌图片、完整流程及两张不同节点图片；后台继续覆盖1440×1000、1280×900、1024×768布局。
